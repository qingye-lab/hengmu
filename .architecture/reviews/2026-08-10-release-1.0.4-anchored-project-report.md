## Selector source verification

The previous pre-anchor candidate was not reused. Direct Git inspection proves
the replacement anchor chain:

- `resources/selector-source.json` at `538886f` binds commit
  `45c427396a7eb5fc500ed2ab4b6375720bfc310c` and plugin version `1.0.4`.
- `45c4273` is an ancestor of `538886f`.
- `.codex-plugin/plugin.json` at `45c4273` declares version `1.0.4`.
- That manifest's SHA-256 is
  `ec5218c0df14ace8b79922be8f68e0f5dfaa7ca646e3b12dd2883b053f0c9546`,
  exactly the Selector Runtime lock value.
- The Selection binds the reviewed project commit `538886f`, the anchored
  Profile and facts, and the current selector implementation bundle.

This contradicts the strongest anchor-specific counter-hypothesis: that the
Selection could claim 1.0.4 while replaying a non-ancestor or a source commit
whose native manifest still declared another version.

## Strongest broader counter-hypothesis

The remaining plausible adverse explanation was that a mechanical-looking
patch concealed version drift, a mutable or incorrect attestation dependency,
expanded workflow authority, package incompatibility, or an over-broad host
claim.

Direct evidence contradicts those branches:

- All active version surfaces inspected at `538886f` declare 1.0.4, while
  retained 1.0.3 text is explicitly historical release and benchmark evidence.
- Official GitHub metadata maps `actions/attest` tag `v4.2.2` to the exact
  signed commit `1e69f48acb82d1966a394da916b4c1698aa569d6` used at all three call sites.
- Upstream `action.yml` has the same SHA-256 at the old v4.2.1 and new v4.2.2
  commits, so the action input interface did not change.
- Release permissions remain limited to `attestations`, `contents`, and OIDC
  writes, after the full quality, package, checksum, license, and SPDX chain.
- The dated host evidence names Codex CLI 0.147.0, macOS 27.0 arm64, the exact
  package digest, read-only routing outcome, restoration, and unavailable or
  untested hosts. The current CLI and OS identify as those recorded values.

Actual tag-triggered action execution cannot be established before publication.
That branch is retained as an unknown rather than promoted to a finding or
silently claimed as passing.

## Strengths

- The Selector Runtime anchor is an actual ancestor whose native manifest hash
  and version match the 1.0.4 Selection lock.
- Native and portable manifests, CLI output, templates, benchmark defaults,
  documentation, and contract tests use one version identity.
- The release action is pinned to a full, signed upstream commit at all three
  provenance/SBOM call sites.
- The release chain orders validation, tests, dependency/license audit,
  deterministic packaging, smoke tests, checksums, and SPDX generation before
  attestation and publication.
- Host evidence is deliberately time- and host-bounded and records restoration
  after a temporary Codex marketplace installation.
- Candidate, Profile, facts, Rule Packs, Knowledge Selection, selected entries,
  and every assessed source row are hash-bound to the reviewed snapshot.
