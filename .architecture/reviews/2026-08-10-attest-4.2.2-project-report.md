## Architecture and change path

The architecture remains:

`manifest -> focused Skill -> shared schema/knowledge/CLI contracts -> deterministic validation and packaging -> checksum/SBOM -> GitHub attestation -> release`

The only modified boundary is the external action implementation invoked at
the attestation step. Workflow trigger, permissions, quality gate, archives,
checksum, SBOM generation, subject paths, SBOM paths, and release publication
remain byte-for-byte unchanged around the three pin substitutions.

## Strongest counter-hypothesis

The strongest plausible benign-to-adverse alternative was that the apparent
patch update either targeted a commit other than official `v4.2.2`, silently
changed the action input contract, changed workflow authority or attestation
subjects, or introduced a release-runtime incompatibility hidden by the small
repository diff.

The first three branches are contradicted by direct evidence:

- `git diff origin/main...HEAD` reports one file and three pin substitutions.
- `git ls-remote https://github.com/actions/attest.git refs/tags/v4.2.1 refs/tags/v4.2.2` maps the two tags exactly to the old and new full commits.
- The upstream `action.yml` is identical between the two commits; `subject-path`
  and `sbom-path` retain their meanings and the Node 24 runtime is unchanged.
- The PR's hosted dependency review passed, while all six matrix jobs reached
  the architecture gate before failing on review freshness rather than tests.

The remaining runtime branch cannot be disproved without executing a real
tag-triggered release. Upstream `v4.2.2` changes bundled dependencies and its
distribution, so this is retained as an explicit unknown rather than converted
into a finding. The next governed release is the end-to-end proof.
